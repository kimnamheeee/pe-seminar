# Core validation — current pitch

## 실험

서울역→강남역을 대상으로 Kakao 대중교통 경로를 조회하고, 60분 미만 첫 경로 하나에서 음식점 카테고리(FD6)를 한 번 검색했다. 해당 경로의 좌표 형상과 검색된 식당 좌표 사이의 거리를 계산했다. 실행 스크립트는 `scripts/verify-core-flow.mjs`, 결과 원본은 [`current-core-validation.json`](current-core-validation.json)이다.

## 결과

- 대중교통 API: HTTP 200, 경로 15개 반환. 이 중 11개가 60분 미만이었다. 첫 옵션은 36분 39초, 환승 1회였다.
- 식당 검색: 선택 경로의 사각형 범위로 1회 호출. 첫 페이지 15개를 받았고, 경로선에서 1km 이내인 후보는 5개였다. API의 `total_count`는 16,858, `pageable_count`는 45였다. 결과가 없으면 추가 검색을 하지 않는 동작을 적용할 수 있다.
- 하차 정류장: 선택 경로 응답의 정류장 13개는 모두 `name` 필드만 포함했고 좌표·ID가 없었다. 가장 가까운 정류장까지의 도보 경로를 계산할 수 없었다.

## 결정

경로 조회와 경로 주변 식당 후보 탐색은 한 경로의 실호출로 동작 가능성을 확인했다. 식당 후보는 경로선 기준 1km 이내로 제한한다. 정류장 추천은 필요한 좌표가 응답에 없어 MVP에서 제외한다. 정류장 데이터 연동이나 다른 API 조합은 이번 범위에 추가하지 않는다.
