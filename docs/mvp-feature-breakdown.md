# 가는김에 MVP 기능 분해

> **상태:** 구현 계획 초안. 사용자 결정은 확정 기준으로, 구현 상태는 2026-11-14 코드 기준으로 적었다. 각 단위는 사용자에게 확인 가능한 세로 기능을 지향한다. 이 문서는 구현 완료나 테스트 통과를 뜻하지 않는다.

## 목표와 범위

사용자가 서울 안의 출발지와 도착지를 직접 선택하고, 그 좌표에 맞는 60분 미만의 버스·지하철·혼합 경로를 찾아 선택한 뒤, 경로 주변 식당과 알맞은 하차 정류장·역을 확인한다.

- 두 테스터가 각자 장소를 자유롭게 선택하는 것이 경로 탐색 검증의 일부다.
- Kakao Local 장소 검색 결과를 선택해 좌표를 얻고, Kakao 대중교통 경로 API에 전달한다.
- 식당 후보 검색은 현재 구현 기준인 500m 경로 샘플 간격, 샘플 지점 반경 300m, 경로선 200m 이내, 샘플 구간별 최근접 최대 5곳이다.
- 매칭된 하차 지점과 식당 사이 직선거리가 400m 이상이면 식당 후보에서 제외한다. 하차 매칭 실패 시 식당은 유지한다.
- 로그인, 검색 기록, 식당 경유 재경로 최적화는 MVP 범위에서 제외한다.

|---|---|---|---|

| 5 | 동적 식당 카테고리 필터 | 결과 카테고리 칩·다중 선택·가로 스크롤을 구현하고, 지도와 목록에 같은 필터를 적용. 타입 검사는 통과했으며, 모든 필터 조합의 사용성 확인은 남음 | 4 |

기능 1→4를 먼저 연결하면 사용자가 직접 고른 장소에서 식당·하차 안내까지 이어지는 핵심 세로 흐름이 생긴다. 기능 5와 6은 그 흐름에 확정된 탐색·후보 정책을 더한다. 기능 7은 기존 화면의 제한된 오류 처리와 전체 상태를 맞춘다.

## 기능 1 — 출발지·도착지 검색 및 장소 선택

**사용자 스토리**

> 서울에서 이동하려는 사람으로서 출발지와 도착지를 검색 결과에서 선택하고, 필요하면 현재 위치를 출발지로 사용하고 싶다. 내가 의도한 장소의 좌표로 경로를 찾기 위해서다.

**동작**

- 출발지와 도착지를 각각 검색한다.
- 출발지와 도착지를 선택한 후 홈의 `출발지·도착지 바꾸기` 버튼으로 두 장소를 즉시 교환할 수 있다.
- 홈은 지도보다 두 장소 입력을 중심으로 둔다. 출발지 검색이 기본이고 `현재 위치`는 보조 동작이다.
- `현재 위치`는 사용자가 눌렀을 때만 위치 권한을 요청한다. 성공하면 받은 좌표를 출발지로 사용한다.
- Kakao Local 결과에서 장소명과 주소를 함께 보여준다. 도로명 주소가 있으면 우선 표시하고, 없으면 지번 주소를 표시한다.
- 서울 안의 장소만 선택 가능하다.
- 입력 문자열이 아니라 선택한 장소의 좌표를 다음 경로 검색에 넘긴다.

**완료 조건**

- **Given** 사용자가 검색어를 입력하고 서울 안 검색 결과가 돌아오면, **When** 결과를 확인할 때, **Then** 장소명과 주소를 보고 구분할 수 있다.
- **Given** 검색 결과가 있으면, **When** 사용자가 한 장소를 선택할 때, **Then** 선택된 장소가 출발지 또는 도착지 입력으로 확정된다.
- **Given** 사용자가 출발지의 `현재 위치`를 직접 누르면, **When** 위치 권한과 현재 위치 조회가 성공할 때, **Then** 해당 좌표를 출발지로 선택한다.
- **Given** 위치 권한이 거부되거나 위치 조회에 실패하면, **When** 오류가 발생할 때, **Then** 이유를 안내하고 장소명 검색을 계속할 수 있다.
- **Given** 출발지와 도착지가 모두 선택되지 않았으면, **When** 사용자가 경로 찾기를 시도할 때, **Then** 경로 요청을 보내지 않고 필요한 선택을 안내한다.
- **Given** 서울 안 검색 결과가 없으면, **When** 검색이 완료될 때, **Then** 장소 없음 상태를 보여주고 검색어를 수정할 수 있다.
- **Given** 장소 검색 API가 실패하면, **When** 오류가 발생할 때, **Then** 검색어를 유지하고 재시도할 수 있다.

**현재 상태와 구현 후보**

- 홈에서 출발지·도착지를 열어 검색어를 입력하고, 서울 검색 결과의 장소명·주소를 확인해 선택할 수 있다. 검색은 300ms 디바운스하며 로딩·결과 없음·오류와 재시도 상태를 제공한다.
- `mobile/convex/places.ts:searchPlaces` action을 클라이언트에 연결했다. 선택한 장소의 좌표를 `routes.getRoutesWithStatus`에 전달하며 경로 제목과 지도 출발·도착 마커도 선택 장소를 사용한다. 기존 `getRoutes` action은 배열 응답 호환용으로 유지한다.
- 현재 위치 버튼은 사용자가 눌렀을 때만 foreground 권한을 요청하고, 현재 좌표를 출발지로 설정한다. 출발지 입력에는 `현재 위치`라고 표시한다. 백그라운드 위치 추적은 하지 않는다.
- 위치 권한 거부와 위치 조회 실패를 출발지 입력 아래에 안내한다. Kakao 장소 검색으로 출발지를 정하는 흐름은 계속 사용할 수 있다.
- 검색 중 뒤로 가면 기존에 확정한 장소 선택을 유지한다. 다른 결과를 선택하면 해당 장소와 좌표를 교체한다.
- 이미 선택한 출발지·도착지를 다시 검색하면 기존 장소명을 검색어로 미리 채우고, 새 장소를 선택하기 전까지 원래 선택을 유지한다.

## 기능 2 — 선택 장소 기반 경로 검색과 결과 상태

**사용자 스토리**

> 장소를 선택한 사람으로서 그 좌표 사이의 대중교통 경로를 보고 싶다. 내가 선택한 장소 조합이 실제로 연결되는지 확인하기 위해서다.

**동작**

- 선택 장소 좌표로 Kakao 대중교통 경로 API를 호출한다.
- 전체 시간이 60분 미만인 경로만 사용자 결과로 제공한다.
- 경로가 없는 경우와 경로는 있지만 모두 60분 이상인 경우를 구분한다.
- API 오류는 경로 없음과 구분하고, 선택한 장소를 보존해 재시도한다.

**완료 조건**

- **Given** 출발지와 도착지가 선택되어 있으면, **When** 경로 찾기를 누를 때, **Then** 두 선택 좌표로 경로를 요청한다.
- **Given** 60분 미만 경로가 있으면, **When** 응답이 도착할 때, **Then** 해당 경로 선택지를 보여준다.
- **Given** 대중교통 경로 응답이 비어 있으면, **When** 응답이 도착할 때, **Then** 두 장소 사이에 경로가 없다고 안내하고 장소 수정으로 돌아갈 수 있다.
- **Given** 경로는 있지만 모두 60분 이상이면, **When** 결과를 만들 때, **Then** “60분 미만 경로 없음” 상태로 구분해 안내하고 장소 수정으로 돌아갈 수 있다.
- **Given** 경로 API 요청이 실패하면, **When** 오류가 발생할 때, **Then** 선택 장소를 유지하고 재시도할 수 있다.

**현재 상태와 구현 후보**

- `mobile/convex/routes.ts:getRoutesWithStatus`는 좌표를 받아 경로 유형·단계·형상과 `FOUND`, `NO_ROUTES`, `ALL_TOO_LONG` 상태를 반환한다. 기존 설치 앱 호환을 위해 `getRoutes`는 배열 응답을 유지한다.
- 앱은 기능 1에서 선택한 장소 좌표를 `getRoutesWithStatus`에 전달한다. 기존 `getRoutes` action은 배열 응답 호환용이다.
- 앱은 경로 없음과 모든 경로가 60분 이상인 경우에 서로 다른 안내를 표시한다. API 오류는 별도 오류 화면과 재시도로 처리하고 선택 장소를 보존한다.
- 타입 검사는 통과했고 iOS 시뮬레이터용 개발 빌드와 실행도 확인했다. 임의의 여러 장소 조합에서 경로 응답의 정확성을 확인하는 작업은 남아 있다.

## 기능 3 — 경로 유형 탭과 경로 개수

**사용자 스토리**

> 경로를 비교하는 사람으로서 전체 경로를 먼저 보고, 원하면 버스·지하철·혼합 유형별로 좁혀 보고 싶다. 잘못된 유형 탭을 눌러 탐색을 헤매지 않기 위해서다.

**동작**

- 네 탭을 `전체`, `버스`, `지하철`, `버스 + 지하철` 순으로 제공한다.
- 첫 진입 시 `전체`를 선택한다.
- 각 탭에 해당하는 60분 미만 경로 수를 표시한다.
- 경로 수가 0인 유형 탭은 비활성화한다. 전체 결과가 0이면 기능 2의 세부 빈 상태를 보여준다.
- 경로 카드는 소요 시간, 환승 수, 교통수단 정보를 비교 가능하게 보여준다.

**완료 조건**

- **Given** 60분 미만 경로가 반환되면, **When** 경로 선택 화면이 열릴 때, **Then** 네 탭 중 `전체`가 선택된 상태로 보인다.
- **Given** 유형별 경로가 있으면, **When** 탭을 볼 때, **Then** 해당 유형의 경로 개수가 표시된다.
- **Given** 특정 유형 경로가 0개이면, **When** 탭을 볼 때, **Then** 탭은 보이되 비활성화되어 선택할 수 없다.
- **Given** 유형 탭을 선택하면, **When** 선택이 적용될 때, **Then** 해당 유형 경로만 목록에 남고 개수 표시와 목록이 일치한다.
- **Given** 경로가 하나도 없으면, **When** 경로 검색이 끝날 때, **Then** 빈 유형 탭 화면 대신 기능 2에서 정한 전체 경로 없음 상태를 보여준다.

**현재 상태와 구현 후보**

- `mobile/convex/routes.ts`는 `BUS`, `SUBWAY`, `BUS_AND_SUBWAY` 유형을 반환한다.
- `mobile/src/components/RouteTypeTabs.tsx`에 네 탭, 숫자, 0개 비활성화를 구현했다.
- `mobile/src/app/index.tsx`는 60분 미만 응답의 유형별 개수를 계산하고, `전체` 또는 선택 유형에 맞춰 경로 카드를 필터링한다. 새 경로 검색은 `전체`로 초기화하며 식당 화면에서 돌아오면 선택 탭 상태를 유지한다.
- 타입 검사는 통과했고 iOS 시뮬레이터용 개발 빌드와 실행도 확인했다. 0개 유형 탭 등 경계 사례의 반복 검증은 별도로 하지 않았다.

## 기능 4 — 선택 경로의 식당 목록과 지도

**사용자 스토리**

> 경로를 고른 사람으로서 이동 경로 주변 식당을 지도와 목록에서 탐색하고 싶다. 경로를 벗어나 다시 검색하는 수고를 줄이기 위해서다.

**동작**

- 선택한 경로의 형상을 식당 검색에 넘긴다.
- 현재 정책대로 500m 간격 샘플 점에서 반경 300m를 검색하고, 경로선 200m 이내 후보 중 각 샘플 구간 최근접 최대 5곳을 반환한다.
- 후보를 출발지에서 도착지 방향의 경로 순으로 정렬한다.
- 서버 반환 후보를 목록에 모두 표시하며, 지도 핀과 목록 항목의 선택 상태를 연결한다.
- 식당 결과 없음과 검색 오류를 구분한다.

**완료 조건**

- **Given** 사용자가 경로를 고르면, **When** 식당 검색이 진행될 때, **Then** 로딩 상태를 보여준다.
- **Given** 식당 후보가 반환되면, **When** 결과 화면이 표시될 때, **Then** 목록은 경로 순이고 반환된 후보가 모두 탐색 가능하다.
- **Given** 목록의 식당을 선택하면, **When** 선택 상태가 바뀔 때, **Then** 같은 식당 핀이 지도에서 강조된다.
- **Given** 경로 주변 후보가 없으면, **When** 검색이 성공적으로 끝날 때, **Then** 식당 없음 상태와 다른 경로를 고를 방법을 보여준다.
- **Given** 식당 검색 API가 실패하면, **When** 오류가 발생할 때, **Then** 정상 빈 결과와 구분하고 재시도 방법을 제공한다.

**현재 상태와 구현 후보**

- `mobile/convex/restaurants.ts:getRestaurantsWithStops`가 현재 앱에서 사용하는 식당 검색·하차 매칭 흐름이다. 구버전 클라이언트 호환용 `getRestaurants` action도 유지한다.
- `mobile/src/app/index.tsx`에는 선택 좌표 경로를 이용한 지도·바텀시트·목록 정렬·지도 동기화가 구현되어 있다.
- 현재 항목은 500m 간격 샘플당 최대 5곳으로 제한된다. “서버 반환 결과 전부 표시”는 Kakao에 등록된 식당 전체를 의미하지 않는다.

## 기능 5 — 식당 카테고리 필터

**사용자 스토리**

> 식당을 탐색하는 사람으로서 결과에 실제 있는 음식 카테고리 중 몇 가지를 골라 보고 싶다. 관심 없는 후보를 빠르게 줄이기 위해서다.

**동작**

- 현재 결과의 카테고리만 중복 제거해 칩으로 만든다.
- 칩은 바텀시트 핸들 바로 아래 고정 행에 둔다.
- 여러 칩을 선택하면 선택한 범주 중 하나라도 일치하는 식당을 보여준다.
- 처음과 선택된 칩이 없는 상태에서는 전체 식당을 보여준다.

**완료 조건**

- **Given** 식당 결과에 여러 카테고리가 있으면, **When** 필터 행이 표시될 때, **Then** 결과에 실제 포함된 서로 다른 카테고리만 칩으로 보인다.
- **Given** 여러 카테고리 칩을 선택하면, **When** 필터가 적용될 때, **Then** 선택한 카테고리 중 하나라도 해당하는 식당이 표시된다.
- **Given** 칩 선택이 모두 해제되면, **When** 필터가 적용될 때, **Then** 필터 없이 전체 식당이 표시된다.
- **Given** 목록을 스크롤해도, **When** 바텀시트 목록이 움직일 때, **Then** 고정 필터 행은 계속 접근 가능하다.
- **Given** 식당 결과가 없으면, **When** 필터를 만들 때, **Then** 고를 카테고리 칩을 만들지 않는다.

**현재 상태**

카테고리 값은 Kakao Local `category_name`의 두 번째 단계에서 추출한다. 결과에 있는 값만 칩으로 만들며, 선택 카테고리 중 하나라도 일치하는 식당을 목록과 지도에 표시한다. 선택을 모두 해제하면 전체를 표시한다. 칩은 핸들 바로 아래 고정 행에 있고, 넘치는 경우 해당 행을 가로 스크롤한다. 새 경로를 선택하면 필터를 초기화한다. 타입 검사는 통과했으며 실제 기기 조작 확인은 남아 있다.

## 기능 6 — 식당 선택과 하차 정류장·역 안내

**사용자 스토리**

> 식당을 고른 사람으로서 그 식당에 가기 위해 어느 정류장이나 역에서 내릴지 같은 화면에서 확인하고 싶다. 식당을 골라도 하차 지점을 다시 찾아야 하는 불편을 피하기 위해서다.

**동작**

- 선택 경로 단계가 `BUS`이면 버스 데이터, `SUBWAY`이면 지하철 데이터에서 이름 후보를 찾는다.
- 동명 후보가 있으면 경로 형상에 가장 가까운 좌표 후보를 초기 매칭으로 쓴다. 경로 후보 거리 상한은 두지 않고 사용자 테스트 경로에서 확인한다.
- 식당의 경로 진행률 앞뒤로 후보 구간을 제한하지 않는다. 경로에 포함된 모든 버스 정류장·지하철역 중 식당과 가장 가까운 후보를 고른다.
- 선택한 식당의 하차 안내를 별도 상세 화면 없이 같은 결과 화면에서 보여준다.
- 매칭된 하차 지점과 식당의 직선거리가 400m 이상이면 해당 식당을 후보에서 제외한다. 매칭 자체에 실패하면 기존 합의대로 식당은 남기고 하차 안내를 찾지 못했다고 표시한다.
- 경로가 서울 경계를 벗어나면 경로·식당 탐색은 유지하고 하차 안내가 제한된 이유를 표시한다.
- 경계 판별은 서울 자치구 2017 GeoJSON을 사용한다. 경로 형상 점과 긴 선분의 100m 간격 표본을 검사한다. [원본 경계 데이터](https://github.com/datainworld/administrative_district/tree/master/3_%EC%84%9C%EC%9A%B8%EC%8B%9C_%EC%9E%90%EC%B9%98%EA%B5%AC) 기준이므로 최신 공식 경계로 교체하기 전까지는 근사 판별이다.

**완료 조건**

- **Given** 버스 단계가 있는 경로에서 하차 후보를 조회하면, **When** 후보가 매칭될 때, **Then** 버스 정류장 데이터로 안내한다.
- **Given** 지하철 단계가 있는 경로에서 하차 후보를 조회하면, **When** 후보가 매칭될 때, **Then** 지하철역 데이터로 안내한다.
- **Given** 사용자가 식당을 선택하면, **When** 하차 정보가 준비될 때, **Then** 같은 결과 화면에서 하차 지점과 지도 강조를 볼 수 있다.
- **Given** 매칭된 하차 지점과 식당이 직선거리 400m 이상이면, **When** 후보를 구성할 때, **Then** 해당 식당은 목록에서 제외된다.
- **Given** 하차 정류장·역 매칭이 실패하면, **When** 결과를 구성할 때, **Then** 식당을 유지하고 하차 안내 불가 상태를 표시한다.
- **Given** 경로가 서울 경계를 벗어나면, **When** 식당 결과가 표시될 때, **Then** 경로와 식당은 유지하고 하차 안내 제한을 알린다.

**현재 상태와 구현 메모**

- `mobile/convex/transitStops.ts:getNearestStopsForRestaurants`와 `mobile/src/app/index.tsx`의 지도·목록 연동은 현재 앱에 구현되어 있다.
- `mobile/convex/restaurants.ts:getRestaurantsWithStops`가 식당 검색과 하차 매칭을 연결하고, 매칭된 하차 지점이 400m 이상인 식당만 후보에서 제외한다. 매칭 실패 식당은 유지한다.
- 지하철역 `normalizedName`은 역 이름에서 괄호 별칭을 제거해 저장한다. 기존 개발 DB 784건 중 84건을 마이그레이션했고, 낙성대→서울역 2호선·4호선 경로 재조회에서 이수·동작·이촌·숙대입구를 포함한 9개 역으로 식당 후보가 매칭됨을 확인했다.
- 앱은 필터된 식당과 해당 하차 정보를 같은 응답에서 받아 목록·지도에 사용한다. 구버전 클라이언트 호환을 위해 기존 `getRestaurants` 액션은 유지했다.
- 경로가 서울 경계를 벗어나면 서버는 식당을 유지하고 하차 매칭·400m 필터를 건너뛴다. 결과 화면에 안내 제한 이유를 보여준다. 경계 데이터는 `mobile/convex/data/seoul-districts-2017.json`에 둔 2017 자료이며 최신 공식 경계로 교체할 필요가 있다.

## 기능 7 — 통합 빈 결과·오류 복구와 사용자 검증

**사용자 스토리**

> 탐색 중 문제가 생긴 사람으로서 무엇이 실패했는지 알고 다시 시도하거나 입력을 고치고 싶다. 경로가 없다는 상황과 일시적인 오류를 구분하기 위해서다.

**완료 조건**

- **Given** 장소 검색 결과가 없으면, **When** 검색이 성공적으로 끝날 때, **Then** 검색어를 수정할 수 있다.
- **Given** 대중교통 경로가 없거나 모두 60분 이상이면, **When** 결과를 안내할 때, **Then** 두 상태를 각각 설명하고 출발지·도착지 수정으로 연결한다.
- **Given** API 오류나 시간 초과가 발생하면, **When** 오류 상태를 보여줄 때, **Then** 빈 결과와 구분하고 관련 입력을 보존한 재시도를 제공한다.
- **Given** 두 테스터가 각각 직접 고른 서울 장소를 사용하면, **When** 전체 흐름을 진행할 때, **Then** 입력 장소에 맞는 경로가 나오는지, 식당 선택과 하차 지점까지 이해하는지 관찰할 수 있다.
- **Given** 두 테스트가 끝나면, **When** 결과를 정리할 때, **Then** 멈춘 지점과 가장 큰 장애물, 수정 내용, 전후 캡처를 `docs/04-notes.md`에 기록한다.
