# 하차 정류장 매핑 후속 검토

## 목적

가는김에는 대중교통 경로와 식당을 따로 찾아 비교하느라 길찾기를 멈춰야 하는 불편을 줄이려는 서비스다. 경로 주변 식당만 보여주고 그 식당에 가려면 어느 정류장에서 내려야 하는지 알려주지 않으면, 사용자는 하차 지점을 다시 별도로 검색해야 한다. 식당을 찾는 수고는 줄어도 처음 해결하려던 불편이 반복되므로 문제를 충분히 해결했다고 보기 어렵다. 따라서 식당에 들르기 좋은 하차 정류장 안내는 부가 기능이 아니라 문제 해결을 완성하는 핵심 기능이다.

아래 검토는 이 기능을 넣을지 판단하기 위한 것이 아니라, 구현에 쓸 정류장 좌표와 매핑 방식이 실제로 작동하는지 확인하기 위한 것이다.

## 현재 확인된 점

- 기존 Kakao 대중교통 경로 응답 샘플에서 정류장 13개는 이름만 포함하고 좌표와 ID는 제공하지 않았다 ([검증 기록](samples/current-flow-validation.md)).
- 좌표를 얻기 위해 [TMAP 대중교통 API](https://transit.tmapmobility.com/docs/routes)로 전환하는 방안을 검토했다. 하지만 무료 요금제의 대중교통 경로 API 한도가 하루 10회라, 사용자의 길찾기 요청마다 API를 호출하는 방식은 한도에 걸릴 수 있다고 판단해 TMAP을 선정하지 않았다 ([요금제 안내](https://transit.tmapmobility.com/)).
- 정류소 위치정보는 경로 탐색 결과처럼 매 요청마다 최신 조회가 필요한 값은 아니므로, 요청 때마다 외부 API를 호출하는 대신 정적인 공개 데이터를 DB에 넣어 조회하는 방안을 검토한다. 공개 정류소 데이터가 자주 바뀌지 않는다는 전제와 갱신 요건은 실제 운영 전에 확인한다.
- 후보 데이터로 [서울시 버스정류소 위치정보](https://data.seoul.go.kr/dataList/OA-15067/A/1/datasetView.do)를 발견했다. 버스 정류소 좌표와 정류소 ID를 제공하며, 정류소 이름은 중복될 수 있으므로 이름만으로 레코드를 고유하게 식별할 수 없다.
- 이번 검토는 같은 이름의 정류소가 여러 곳에 있어 경로 기준으로 후보를 구분해야 하는 버스 정류소 문제에 집중한다. 지하철역은 역명이 고유해 같은 이름 후보를 경로로 구분하는 동일한 문제가 없으므로 이번 데이터 매핑 검토 범위에 포함하지 않는다.

## 검증 가설

Kakao 응답의 정류장 이름으로 서울시 데이터에서 후보를 찾고, 후보 좌표와 선택 경로의 형상 및 경로상 순서를 비교하면 같은 이름의 정류장 중 실제 경로에 해당하는 정류장을 추릴 수 있을 것이다.

이름은 검색 조건으로만 쓰고 고유 키로 사용하지 않는다. 후보가 여러 개일 때 경로와의 근접도 및 순서를 이용해 선택할 수 있는지 확인하며, 근거가 부족한 경우에는 잘못된 정류장을 확정하지 않는 기준도 검토한다.

## 검증 계획

실제 Kakao 길찾기 응답 50~100개를 표본으로 모아 응답에 포함된 버스 정류장 이름과 서울시 버스정류소 데이터의 레코드를 비교한다. 이번 검증은 이름이 중복될 수 있는 버스 정류소에 집중한다.

측정 지표는 정류장 단위로 계산한다.

- **매핑 성공률:** 데이터셋 후보를 찾고, 경로 형상·순서 비교로 타당한 좌표를 연결한 정류장 비율
- **복수 후보 발생률:** 같은 이름으로 둘 이상의 데이터셋 레코드가 검색된 정류장 비율
- **미매칭 비율:** 이름으로 후보 레코드를 찾지 못한 정류장 비율

복수 후보 중 선택한 좌표가 실제 경로의 정류장과 일치하는지도 표본을 대조해 확인한다. 전체 수치와 함께 이름 중복, 경로 형상 근접도, 정류장 배열 순서가 매칭에 주는 영향을 살펴보고 데이터셋 채택 여부와 매칭 규칙을 정한다.

## 데이터 운영 요건

서울시 데이터셋을 채택하면 1만 건이 넘는 정류소 레코드를 앱에 싣지 않고 DB에 적재해 서버에서 조회한다. 서울시 정류소 ID를 레코드 식별자로 보존하고 정류소 이름은 고유하다고 가정하지 않는다.

데이터 제공처에서 새 파일이 공개될 때 DB를 갱신할 수 있어야 한다. 갱신은 새 버전을 반영한 뒤 기존 데이터와 교체하는 흐름을 기본 방향으로 검토하며, 실제 적재 도구와 갱신 주기는 검증 결과와 배포 운영 방식에 맞춰 결정한다.

## 다음 결정

표본 검증 결과를 바탕으로 다음을 결정한다.

1. 서울시 버스정류소 데이터셋을 매핑에 채택할지
2. 이름 후보와 경로 형상·순서를 결합하는 매칭 규칙 및 불확실한 후보의 처리 기준
3. DB 적재·조회 구조와 새 데이터 공개 시 갱신 절차
